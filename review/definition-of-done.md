## 线 B：Agent 快速构建 Rust 能力证明 —— 状态：差最后一公里（~80%）

### 工程骨架（已达标）
- [x] binary/library 分离（`main.rs` 4 行 + `lib.rs`）
- [x] 三层架构 `db → services → web/handlers`
- [x] 目录模块 + `pub(crate)` / `pub(super)` 可见性分级
- [x] `build_router` 抽离，路由可测试
- [x] 单元 + HTTP 集成测试（共 14：10 单元/服务 + 4 集成）
- [x] GitHub Actions CI（fmt / check / test / clippy -D warnings）
- [x] WORKLOG 记录每轮 Goal / Completed / Verification
- [x] 评审驱动的迭代闭环（三轮 review → 落地 → 验证）

### 收工前建议补齐（按优先级）
- [ ] **【最高】`thiserror` 类型化错误**：把 service 层 `Result<(), String>` 换成 `enum LibError { NotFound, RuleViolation(String), Db(#[from] rusqlite::Error) }`，handler 据此映射 HTTP 状态码（404 / 400 / 500）。这是能力证明里展示价值最高的一项。
- [ ] **【中】安全短板二选一：补齐或诚实标注**
  - [ ] 密码哈希换 `argon2` / `bcrypt`（慢哈希 + 每用户独立盐），替换当前 `SHA-256 + 固定盐`
  - [ ] 会话加过期机制 / 持久化（当前内存 `HashMap`，进程重启即失效）
  - [ ] 或：在 README 标注为「已知限制 / 后续工作」，作为工程判断的诚实展示

### 明确不做（避免过度工程）
- [~] 连接池（r2d2 / deadpool）：SQLite + 当前并发收益最低，**建议不做**；若做需在报告说明动机
- [~] Cargo 工作区拆分：单 crate 规模未到，不必要

> 判定：补齐「thiserror」一项 + 安全短板任一处理方式，B 线即可收工。
